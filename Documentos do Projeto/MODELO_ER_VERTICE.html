Diagrama de relacionamento

O banco de dados do Vértice possui 8 tabelas inter-relacionadas. A estrutura foi montada pra suportar chat em tempo real, fórum de perguntas e respostas, repositório de arquivos e um sistema auditável de moderação.

+-----------------+ 1:N +-----------------+ 1:N +-----------------+ | categories |────────────────>| channels |────────────────>| messages | | (Disciplinas) | | (Salas de chat) | | (Tempo real) | +-----------------+ +-----------------+ +-----------------+ | | | 1:N | N:1 v v +-----------------+ 1:N +-----------------+ +-----------------+ | topics |────────────────>| replies | | attachments | | (Fórum Q&A) | | (Respostas) | | (Anexos/PDFs) | +-----------------+ +-----------------+ +-----------------+ ^ ^ ^ | | | +-------------------+───────────────+───────────────────────────────────+ | N:1 +-----------------+ +-----------------+ | users |─────────>| moderation_logs | | (Alunos / Adm) | 1:N | (Auditoria) | +-----------------+ +-----------------+

Detalhamento das tabelas

users

Cadastro de alunos, monitores e administradores. Senhas criptografadas com Bcrypt.

  • id — BigInt, chave primária auto-increment
  • name — Nome completo do usuário
  • email — Único no sistema, usado no login
  • phone — Telefone de contato (opcional)
  • password — Hash Bcrypt da senha
  • role — Enum: admin, moderator ou student
  • avatar_url — Caminho da foto de perfil (nullable)
  • created_at, updated_at — Timestamps automáticos do Laravel

categories

Representa as disciplinas do curso (Banco de Dados, Redes, POO etc.).

  • id, name, slug, description
  • color — Cor hexadecimal pra identificar visualmente a disciplina

channels

Salas de conversa vinculadas a uma disciplina. Cada categoria pode ter N canais.

  • id, name, description
  • category_id — FK → categories.id (CASCADE)
  • is_private — Se o canal é restrito a moderadores

messages

Mensagens de chat em tempo real enviadas dentro de um canal.

  • channel_id — FK → channels.id (CASCADE)
  • user_id — FK → users.id (CASCADE)
  • content — Corpo da mensagem (TEXT)
  • is_code_block — Se é um bloco de código
  • code_language — Linguagem do código (nullable)
  • parent_id — FK → messages.id (SET NULL) para respostas encadeadas

topics

Perguntas do fórum de dúvidas. Vinculados a uma categoria.

  • title, body — Título e corpo da pergunta
  • category_id — FK → categories.id
  • user_id — FK → users.id
  • is_solved — Se a dúvida já foi resolvida

replies

Respostas a tópicos do fórum.

  • topic_id — FK → topics.id (CASCADE)
  • user_id — FK → users.id
  • body — Corpo da resposta (TEXT)
  • is_solution — Se foi marcada como solução aceita pelo autor da pergunta

attachments

Tabela polimórfica pra anexos. Pode estar ligada a mensagens, tópicos ou respostas.

  • attachable_type — Classe do modelo (App\Models\Message, Topic ou Reply)
  • attachable_id — ID do registro associado
  • file_path, file_name, mime_type, size_bytes

moderation_logs

Registro de toda ação administrativa. Essa tabela é a base do nosso sistema de moderação transparente.

  • moderator_id — FK → users.id (quem tomou a ação)
  • target_user_id — FK → users.id (quem foi afetado)
  • action — Enum: hide_message, delete_topic, suspend_user, warn_user
  • reason — Justificativa por escrito (obrigatória)
  • details — JSON com dados extras (nullable)

Exemplo de DDL (Tabela messages)

Abaixo está a definição da tabela messages em SQL puro, utilizada com conexão PDO no PHP:

CREATE TABLE messages ( id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY, channel_id BIGINT UNSIGNED NOT NULL, user_id BIGINT UNSIGNED NOT NULL, content TEXT NOT NULL, is_code_block TINYINT(1) DEFAULT 0, code_language VARCHAR(50) DEFAULT NULL, parent_id BIGINT UNSIGNED DEFAULT NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (channel_id) REFERENCES channels(id) ON DELETE CASCADE, FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE, FOREIGN KEY (parent_id) REFERENCES messages(id) ON DELETE SET NULL ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
